# SPEC：WatchHub 2.2.1 — 底栏合并为 4 类（源并入订阅）

- 日期：2026-10-23
- 状态：已确认（grilling 第 1 轮完成）
- 关联版本：versionCode 20201 / versionName 2.2.1
- 作者：lead

## 1. 问题

底栏 5 个 tab：「源」和「订阅」都在处理 RSS——源页配置抓取规则，订阅页阅读文章，用户要在两个页面之间来回跳；同一件事被拆成两个入口。用户明确要求合并成 4 类，统一叫「订阅」。

## 2. 用户场景

1. 用户加一个 RSS：在「订阅」页点添加，自动发现并开始阅读，不需要理解「源」是什么。
2. 用户想改某个订阅的抓取间隔/优先级，或批量编辑 JSON：从订阅页点「源管理」进二级页操作。
3. 用户日常只看文章，底栏少一个 tab，信息更聚焦。

## 3. 验收标准（可执行）

| # | 验收标准 | 验证方式 |

| A2 | 订阅页顶部有「源管理」入口，点击进入源管理二级页，返回键回到订阅页 | 人工：点击/返回 |

## 4. 测试 seam

本次改动是纯 UI 结构（菜单项、Activity 容器、Fragment 托管），没有新的纯逻辑，按 AGENTS §2.2 的 UI 例外处理：不新增单测，靠人工清单 + 既有回归测试。菜单/映射属于声明式配置，无法在 JVM 单测里观察。

## 5. 非目标

- 不改订阅/源的数据模型与既有行为。
- 不做 RSS 过滤、OPML、文章分页（仍属于 2.3.0）。
- 不重做订阅页视觉，只加一个入口。

## 6. 影响面

- 菜单：`res/menu/bottom_nav.xml` 删除 `nav_sources`。
- 主界面：`MainActivity` 移除 `nav_sources → SourcesFragment` 映射；恢复 tab 状态加「id 不存在则回退首页」防御。
- 新增 `SourceListActivity` + `res/layout/activity_source_list.xml`：Toolbar + FragmentContainerView 托管现有 `SourcesFragment`（源页实现零改动）。
- 订阅页：`fragment_subscriptions.xml` 顶部加「源管理」图标按钮；`SubscriptionsFragment` 接线跳转。
- Manifest：注册 `SourceListActivity`。
- 文案：新增 `sources_title`、`subs_manage_sources`。
- 文档：README 界面表、ARCHITECTURE 页面职责表、2.2.0 SPEC 加后续说明。
- 数据/schema：无变化，`versionCode` 20201。

## 7. 边界与失败情况

| 场景 | 期望 |
|---|---|
| 进程恢复时 savedInstanceState 里是已删除的 `nav_sources` | 回退到首页，不崩溃 |
| 源管理页在源被删除后返回订阅页 | 订阅页 onResume 刷新，筛选自动回退「全部」（已有逻辑） |
| 订阅页没有任何源 | 「源管理」入口仍可进入，可添加规则 |
| 没有 RSS 订阅但存在 json/regex/hash 源 | 源管理页可正常管理；订阅页文章列表仍展示这些源的文章（2.1 起的行为） |
