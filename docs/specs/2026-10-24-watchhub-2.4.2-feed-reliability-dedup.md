# SPEC：WatchHub 2.4.2 — 失效源治理（国内可达 + 失败退避）+ 订阅/源管理去冗余

- 日期：2026-10-24
- 状态：已实现（用户提出「功能冗余、链接一直失效，从底层优化」；自主执行，grilling 按人工格式记录于 §11）
- 关联版本：versionCode 20402 / versionName 2.4.2
- 作者：lead

## 1. 问题

用户反馈「有些链接一直在失效、功能有些冗余」。逐条核实后是五个底层问题：

1. **推荐订阅 4/5 是海外源，用户网络永久不可达**（`ui/HubUi.kt:260 recommendedFeeds()`）。
   OpenAI / DeepMind / Hugging Face / TechCrunch 四个 feed 在大陆直连网络不可达（GFW），
   用户点一键订阅后源状态永远「连续 N 次失败」，首页源状态与体检页长期红。
   佐证用户网络环境：荣耀手表（国内市场）、中文内容、`docs/FLCLASH_REFERENCE.md`（代理调研）、
   2.4.0 只敢自动种入量子位（国内源）。从海外网络实测这 5 个 feed 全部 200——
   「验证可抓取」是在错误网络上做的，这是 2.4.0 的根因。
2. **失效源无退避、无终点**（`engine/Poller.kt:tick()`）：源每轮失败后仍按原间隔（最短 60s）
   无限重试，白耗电与流量；对不可达源唯一出路是用户手动停用。
3. **订阅页一屏两份同样的源列表**（`fragment_subscriptions.xml`）：横向订阅卡（管理）+
   筛选 chips（同一批源名再列一遍，仅用于筛选），同一信息渲染两遍。
4. **RSS 双管理入口**：订阅页订阅卡可编辑/暂停/删除 RSS 源，源管理页（`SourcesFragment`）
   又把 RSS 源原样列一遍做同样操作——违反 `docs/ARCHITECTURE.md` 页面职责表
   「一次信息只在一个页面负责，避免同一个 RSS 有两个入口」。
5. **自更新清单线路顺序不合理**（`update/Updater.kt:36 MANIFEST_URLS`）：jsDelivr（国内不稳）排第一、
   每线路 20s 超时 × 3 条线路，检查更新最坏卡近 1 分钟；api.github.com（国内相对最稳、
   且必带最新版与 digest）反而排最后。

## 2. 用户场景

1. 我在订阅页点推荐源，点一个成一个，不再出现「订阅成功但永远抓取失败」的源。
2. 我手机上已有几个被墙的源：它们不再每 15 分钟空转，状态明确告诉我「已降频至每 X 分钟」，
   我开系统代理后它能自动恢复原频率（一次成功即清零）。
3. 我在订阅页只看到一份源列表，点卡片就是筛选，不需要上下两排重复控件。
4. 我改抓取规则（JSON/正则/指纹）时从订阅页进「源管理」，那里只放高级监控源，不再和 RSS 混排。
5. 我点「检查更新」：几秒内出结果，而不是先对着 jsDelivr 等两个 20 秒超时。

## 4. 测试 seam（观察点）

- seam 1：`dev.watchhub.app.core.Backoff.effectiveIntervalSec(baseSec, fails)` —— 新增纯函数，
  退避语义的全部单测都压在这里（core 不依赖 Android）。
- seam 2：`dev.watchhub.app.update.Updater.check/decide/parseGitHubRelease` —— 既有 seam，
  线路重排不改变其语义，回归即可。
- seam 3：`HubUi.recommendedFeeds() / advancedSourceRows() / saveAdvancedSourcesJson()` ——
  静态配置与 UI 门面，按 §2.2 UI 例外走人工清单。
- 不测：Poller 内部 wiring（Android SQLite 依赖）、布局渲染。

## 5. 非目标

- **不删 json/regex/hash 采集器**：番剧更新、补货监控是核心场景，与 RSS 不冗余。
- **不内置代理、不加第三方加速镜像（ghproxy 类）**：代理引入「清单可被镜像篡改」的信任问题，
  且公共镜像本身会失效——那只会制造下一批「一直失效的链接」。需要海外源的用户开系统级
  代理即可（HttpURLConnection/DownloadManager 天然走 VPN）。
- **不自动删除/停用失效源**：无法区分「源真挂了」与「网络环境变了」，自动删数据违反
  「数据库是唯一事实来源」的保守性；退避 + 可见状态已消除其危害。
- 不改调度、升级链、可靠性契约（§4 全部保持）；不做订阅源市场/搜索。

## 6. 影响面

- 模块：`core/`（新增 Backoff）、`engine/Poller`（到期判断）、`ui/HubUi`（推荐源、高级源门面、
  状态文案）、`ui/SourcesFragment`（过滤 RSS）、`ui/SubscriptionsFragment` + `SubscriptionAdapter`
  （删 chips、卡片选中筛选）、`ui/SourceEditActivity`（EDIT_ALL 只编辑高级源）、
  `update/Updater`（线路顺序 + 超时）、`health/Health`（数据源异常文案）。
- 接口变更：无对外接口变更；`HubUi` 新增 `advancedSourceRows()/rawAdvancedSourcesJson()/
  saveAdvancedSourcesJson()`；`recommendedFeeds()` 内容更换。
- schema / 迁移：**无**。退避只读 `source_state.fails`（既有字段）。versionCode 20402。
- 配置格式：SourceDef 无新增/废弃字段。
- UI 页面职责变化：源管理页从「全部源」收窄为「高级监控源（json/regex/hash）」；

## 7. 边界与失败情况

| 场景 | 期望 |
|---|---|
| 源永久不可达（被墙） | 间隔按 2× 起步指数增长到 6h 封顶，不再刷屏失败；状态显示「已降频」 |
| 源恢复（用户开代理） | 下一次（最长 6h 后的）成功即 fails=0，恢复正常间隔；用户可「立即检查」跳过等待 |
| 高频源（60s）退避 | 同样从 2× 起步；60s→2m→4m→…封顶 6h |
| `checkNow` 手动检查 | 忽略退避立即执行（用户显式动作优先） |
| 进程重启 | `lastRun` 本来就在内存，重启后照常首轮检查；退避只依赖落库的 fails，跨重启仍生效 |
| 源管理页全是 RSS 源时 | 空态文案说明「RSS 在订阅页管理」，并提供新增高级源入口 |
| 「编辑全部」里粘贴了 rss 条目 | 合法则按 upsert 语义并入（同名覆盖），保存后出现在订阅页 |
| 「编辑全部」删光高级源 | 只清空高级源，RSS 源原样保留 |
| 推荐源点下去但当前网络不可达 | 沿用现状：discover 失败弹明确错误，不影响手动输入 |
| 旧用户已加了海外源 | 不动其数据；退避自动降低其空转频率，状态可见 |
| 更新检查时 api.github.com 限流/失败 | 落到 jsDelivr、raw 兜底（check() 已有全线路聚合取最新逻辑） |

## 11. 决策记录（人工 grilling：设计树 + 编号提问 + 推荐答案）

Q1 谁在什么网络上用？——推荐列表换国内源的唯一依据。
A：证据链（荣耀手表、中文内容、FlClash 调研、量子位种入）指向大陆直连为主、偶开代理。
若判断错误（用户常驻代理），代价 = 推荐列表少了几个海外源，但手动添加路径不受影响；
反向错误的代价（现状）= 推荐列表 4/5 永久失败。**取换**。风险已在 §9 标注。

Q2 退避会不会拖慢「源恢复了」的发现？
A：会，最长 6h。三个缓解：手动「立即检查」无视退避；成功一次即清零；封顶选 6h 而非 24h
（对 60s 的补货监控，24h 封顶太迟钝）。对「抢票/补货」这种高频场景，6h 封顶意味着
最坏 6 小时才发现源恢复——可接受，因为源挂掉期间本来就抢不到。

Q3 为什么不自动停用/删除失效源？
A：见 §5 非目标。删用户数据不可逆，且「失效」可能是暂时网络问题。退避已消除空转危害。

Q4 为什么不给 App 加代理配置/镜像？
A：§5 非目标。第三方镜像的失效速度比 GitHub 更快，且引入信任问题（清单被镜像篡改 +
APK 被镜像替换的组合风险，除非清单永远走原站——那国内可达性又回到原点）。
系统级代理（FlClash VPN 模式）对本 App 天然生效，不需要 App 自己做任何事。

Q5 删「编辑全部 JSON」还是改语义？
A：改语义（只编辑高级源、保存时保留 RSS）。整包删除会失去「数组级修复」逃生舱；
保留原语义则和「本页只管高级源」矛盾。

Q6 chips 合并后，「全部」入口在哪？
A：点已选中卡片即取消筛选回全部；订阅卡用 MaterialCardView 选中态（描边）呈现。
不另加「全部」伪卡片，避免又造一行控件。

Q7 更小的版本是什么？
A：只做 A1+A2（推荐源 + 退避）已解决「链接失效」主诉；A4–A7 是用户明说的「功能冗余」。
再小就答非所问。更大（代理、自动清理、订阅市场）都进了非目标。
