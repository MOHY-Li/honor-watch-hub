# SPEC：WatchHub 2.2.2 — 修正渠道重要性的体检误报

- 日期：2026-10-23
- 状态：已确认（用户反馈驱动，改动小，按 AGENTS §2.4 走精简流程）
- 关联版本：versionCode 20202 / versionName 2.2.2
- 作者：lead

## 1. 问题

体检页把「提醒渠道重要性 = 默认」判为 WARN，提示用户「调到高，否则手表不震」。
但用户在荣耀手机上反馈：系统通知设置里**只有「默认」，没有「重要/高」选项**，这条永远无法消除。

事实核对：
- 渠道重要性由系统在创建时决定档位、之后由用户调整；部分荣耀/华为 ROM 只暴露「默认」，不会给「高」。
- 通知镜像依赖的是「通知被发出 + 运动健康勾选了 WatchHub」，不是渠道是否为高；高重要性只影响手机端响铃/横幅强度。
- 因此把 DEFAULT 判成异常是误报，会误导用户去改一个不存在的开关。

## 2. 用户场景

1. 荣耀用户打开体检，看到「渠道重要性：默认」告警，但设置里没有「重要」可选项，无法消除。
2. 用户想知道真正该确认什么：测试通知能不能到手表，而不是渠道档位。

## 3. 验收标准（可执行）

| # | 验收标准 | 验证方式 |
|---|---|---|
| A1 | 渠道 importance 为 NONE 判 FAIL（渠道被关闭），提示去开 | `NotificationHealthPolicyTest.classify_off` + 人工 |
| A2 | MIN/LOW 判 WARN（太低），提示可调就调 | `classify_low` |
| A3 | DEFAULT 判 OK，不再告警，文案说明「荣耀常见，不影响镜像」 | `classify_default_isAcceptable` |
| A4 | HIGH/MAX 判 OK | `classify_high` |
| A5 | 体检摘要不再因 DEFAULT 变黄/红 | 人工：荣耀真机（本机无设备，标注未验证） |
| A6 | 既有 140 项单测全绿，assembleDebug / lint 0 error | `:app:testDebugUnitTest` |

## 4. 测试 seam

- `dev.watchhub.app.core.NotificationHealthPolicy`（新增，纯 Kotlin）：
  - `classify(importance: Int): ChannelState`（OFF / LOW / DEFAULT / HIGH）
  - `isAcceptable(state: ChannelState): Boolean`
- 测试只覆盖这个纯函数；`Health` 的 Android 读数与文案走人工清单。

## 5. 非目标

- 不改变渠道创建方式（仍请求 IMPORTANCE_HIGH）。
- 不改变通知内容/镜像策略。
- 不做 ROM 特判（不写 `Build.MANUFACTURER == HONOR` 分支，按 importance 语义判定即可）。

## 6. 影响面

- 新增 `core/NotificationHealthPolicy.kt` + `NotificationHealthPolicyTest`。
- 改 `health/Health.kt` 的 `channelImportance()`：按 policy 分类，文案区分「关闭/太低/默认（正常）/高」。
- 文档：README 安装步骤与体检说明、WATCH_NOTES 渠道条款、AGENTS §5 补 ROM 差异说明。
- 版本 20202 / 2.2.2。

## 7. 边界与失败情况

| 场景 | 期望 |
|---|---|
| API < 26（无渠道概念） | 沿用现有「系统版本较低」OK 项 |
| importance 为未知值（如 6） | 按 HIGH 处理（>=4 即视为可用） |
| 渠道被用户关闭（NONE） | FAIL，仍可点进渠道设置 |
| 渠道低但用户无法调高 | WARN，文案说明「以测试通知是否到手表为准」 |

## 8. 测试计划（红 → 绿）

1. `NotificationHealthPolicyTest.classify_off`（先失败）→ 实现 `classify`
2. `classify_low` / `classify_default_isAcceptable` / `classify_high`（先失败）→ 补齐边界
3. `Health.channelImportance` 接入（人工验证）
4. 全量回归

## 9. 人工验证清单（真机）

| 步骤 | 预期结果 |
|---|---|
| 荣耀手机上打开体检 | 「提醒渠道」显示「默认（荣耀常见）」且为绿色，不再告警 |
| 手动把渠道关掉后再体检 | 显示 FAIL，并能点进渠道设置 |
| 发测试通知 | 手机收到通知、手表震动（验证镜像链路） |

## 10. 发布方式

2.2.2 / versionCode 20202，tag `v2.2.2`；无 schema 迁移，覆盖安装。

## 11. 决策记录

- 不针对荣耀做特判，按 importance 语义把 DEFAULT 视为可用；文案说明真实判定标准是测试通知是否到手表。
