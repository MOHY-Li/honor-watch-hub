# SPEC：WatchHub 2.6.0 — 信息架构向 FlClash 0.9.x 看齐 + 三件基础设施

- 日期：2026-10-25
- 状态：已实现
- 关联版本：versionCode 20600 / versionName 2.6.0
- 作者：lead
- 背景：用户要求参考 FlClash 0.8.97→0.9.x 的 UI/app 层重构（调研记录见 §11），
  健康独立成页、首页并入设置、声明式导航、状态驱动刷新；顺带做配置备份导入、
  状态总线、master 推送 CI。

## 1. 问题

1. **首页职责过载**：开关、下次提醒、体检摘要、源状态、指标、AI 分析全在一页，
   而健康相关内容散落在首页（指标/AI）和任务页（健康规则）两处——域不干净。
2. **导航是硬编码的**：`MainActivity.newFragmentFor()` 的 when 分支 + menu xml 各写一份，
   加 tab 要改两处；FlClash 0.9.x 已改成声明式 `NavigationItem` 列表。
3. **UI 靠轮询刷新**：所有页面 onResume/15s ticker 拉 HubUi，操作后不主动通知，
   FlClash 的做法是状态驱动（页面 watch 状态，写操作 → 状态变 → 自动刷）。
4. **配置没有安全网**：换机/重装/回滚（DB 降级）都丢全部配置，2.5.0 发布时已暴露。
5. **master 推送不跑测试**：只有打 tag 才测，坏提交要到发版才发现。

## 2. 用户场景

1. 打开 App 落在「健康」页：指标、规则、AI 分析、报告，身体相关的都在这一页。
2. 想看今天要做什么 → 「任务」页，顶部一行概览（下次提醒 + 链路状态），下面是提醒规则和任务。
3. 中枢开关、源状态这些「配置与状态」→ 「设置」页顶部「中枢」组。
4. 换手机 → 设置里「导出配置」存一个 JSON，新机「导入」全恢复（API Key 不导出，安全）。
5. 任何页面上做完操作（完成任务/订阅/改规则），所有已打开页面立刻刷新，不用切回来。

## 4. 测试 seam

- seam 1：`core/ChangeBus`（注入投递函数的纯类）——注册/反注册/派发语义。
- seam 2：`engine/ConfigExchange.export/parse`（纯函数，org.json 在本仓库 JVM 测试可用有先例）
  ——round-trip、坏输入、敏感字段排除、合并语义的数据部分。
- seam 3：`HubUi`（门面）、MainActivity 声明式 tab 表——人工清单。
- 不测：Fragment 生命周期接线、SAF 文件选择器、workflow 行为。

## 5. 非目标

- **不引入 Compose/新 UI 框架**：FLCLASH_REFERENCE 已论证单平台 Kotlin 原生；
  本次只学 FlClash 的信息架构与状态驱动思想，不搬 Flutter。
- 不做「可配置导航编辑器」（FlClash 支持用户自定义底栏，我们只做声明式注册，不开放给用户改）。
- 不做设置页搜索、桌面侧栏形态（单手机形态用不上）。
- 状态总线**不覆盖后台轮询产生的新文章**（仍靠 onResume/角标刷新）——总线先服务用户操作路径，
  轮询频率低（分钟级）不值得为它引线程切换复杂度。
- 不做自动云备份/定时备份；导出是手动动作。

## 6. 影响面

- 模块：`MainActivity`（声明式 tab 表）、`menu/bottom_nav.xml`、新增 `HealthFragment` +
  `fragment_health.xml`、删 `HomeFragment` + `fragment_home.xml`、`TasksFragment`（瘦身 +
  概览卡）、`SettingsFragment`（中枢组 + 备份组 + 源状态）、`Container`（+ChangeBus）、
  `HubUi`（写操作发变更 + export/import 门面）、新增 `core/ChangeBus`、`engine/ConfigExchange`、
  `.github/workflows/ci.yml`。
- 接口变更：`HubUi` 新增 `exportConfig/previewImportConfig/applyImportConfig`；
  `Home` 数据类保留（任务概览卡与设置中枢组消费其字段）。
- schema：无变化（备份走既有表）。
- UI 页面职责变化（ARCHITECTURE 同步）：健康=身体域（指标/规则/AI/报告）、任务=时间域（概览+
  提醒+任务）、订阅=内容域、设置=配置与状态域。
- versionCode 20600。

## 7. 边界与失败情况

| 场景 | 期望 |
|---|---|
| 导入文件不是本 App 的 JSON / version 不认识 | 报「不是有效的 WatchHub 配置文件」，不落库 |
| 导入文件里某条源/规则非法 | 整体拒绝（先全量 parse 校验再应用），绝不导一半 |
| 导入与现有重名 | 按 name upsert 覆盖（合并语义），不删除现有未提及项 |
| 导出时用户取消文件选择器 | 无事发生 |
| 页面在后台时收到变更 | 回到前台时 onResume 照样 refresh（双保险） |
| 总线监听者抛异常 | 不影响其他监听者（逐个 runCatching） |
| 旧版本恢复的 `nav_home` id | menu 里不存在 → 回退第一个 tab（健康） |
| 备份文件包含未来的新字段 | parse 忽略未知字段，不炸 |

## 8. 测试计划（红 → 绿顺序）

1. `ChangeBusTest.deliversToRegisteredListeners`（红）→ ChangeBus（绿）。
2. `ChangeBusTest.unregisteredListenerNotCalled` / `postingUsesInjectedExecutor`（红）→ 完善（绿）。

4. `...rejectsBadJson` / `...rejectsUnknownVersion`（红）→ 校验分支（绿）。
5. `...apiKeyNeverExported`（红）→ 导出白名单（绿）。

## 11. FlClash 0.9.x 调研记录（2026-10-25，来源：GitHub releases/源码树）

- UI 重构主线：v0.8.97（2026-09-10）"Rework the app UI + app layer/window handling"，
  v0.9.0/v0.9.1（2026-10）主题与界面全面重构；技术栈未换（Flutter+Riverpod+drift+Go）。
- 新结构：单一 `HomePage` 壳 + 声明式 `NavigationItem{glyph,label,builder,modes}` 列表；
  手机底栏 / 桌面侧栏 / 「更多」由 `modes` 决定；页面常驻（PageLabel + GlobalObjectKey）。
- 页签集合：dashboard/proxies/profiles/tools 在底栏，logs/requests/dns/connections 按形态折叠。
- 配置模型：砍全局覆盖开关改逐项设置（per-key），属破坏性变更。
- 我们抄的：声明式 tab 注册（A1）、状态驱动刷新思想（A5/A11，用 40 行 ChangeBus 而非 Riverpod）；
  不抄的：Flutter/Riverpod 本体、可配置导航编辑器、桌面形态。
