# SPEC：WatchHub 2.4.1 — 同一来源的通知不再堆叠

- 日期：2026-10-23
- 状态：已确认（线上问题，精简流程）
- 关联版本：versionCode 20401 / versionName 2.4.1

## 1. 问题

用户反馈「提醒会直接一发发 4 条」。

根因：Android 通知的身份是 **(tag, id)** 二元组，只固定 tag、id 仍用每条 Alert 的数据库 id
时，同一来源的多条 Alert 会各自成为一条通知。典型触发场景：
- 一个 RSS 源一轮抓到 4 条新文章 → 4 条 Feed Alert → 4 条通知（tag 相同、id 不同）；
- 同一提醒的多次升级 nudge → 每次新 alert id → 多条通知。

这违背 AGENTS §5「同 tag 覆盖、不刷屏」的本意。

## 2. 修复

- 新增 `core/NotificationId.of(tag)`：由 tag 派生稳定通知 id（正整数）。
- `Notifier.show` 用 `NotificationId.of(tag)` 作为 notify id，同 tag 的后续通知**替换**旧通知；
  PendingIntent 的 requestCode 同步改为稳定 id（内容 intent / 操作按钮 / 全屏意图）。
- 不同来源/不同提醒的 tag 不同，仍然是独立通知（这是预期行为）。

## 3. 验收标准

| # | 验收标准 | 验证方式 |
|---|---|---|
| A1 | 同一个 tag 派生出的通知 id 稳定且非负 | `NotificationIdTest.*` |
| A2 | 同一来源一次产生多条 Alert 时，通知栏只保留一条（内容为最新一条） | 人工：RSS 源一轮多更 |
| A3 | 不同来源 / 不同提醒仍是各自的通知，不会互相覆盖 | 人工 |
| A4 | 通知上的「完成/稍后」仍作用于最新一条的任务，点完能取消对应通知 | 人工 |
| A5 | 既有 169 项单测全绿，assembleDebug / lint 0 error | `:app:testDebugUnitTest` |

## 4. 非目标

- 不改 Alert 落库（历史仍保留每条，供后续诊断）。
- 不改不同来源的通知聚合策略。

## 5. 影响面

`core/NotificationId.kt`（新增）+ 测试；`delivery/Notifier.kt`；AGENTS §5 通知 ID 规则更正；
版本 20401 / 2.4.1。无 schema 变更。

## 6. 发布方式

2.4.1 / 20401，tag `v2.4.1`；覆盖安装。
